# zapret.installer — порт для Steam Deck

Порт [Snowy-Fluffy/zapret.installer](https://github.com/Snowy-Fluffy/zapret.installer) под SteamOS.
Меню то же самое, стратегии и списки берутся из [Snowy-Fluffy/zapret.cfgs](https://github.com/Snowy-Fluffy/zapret.cfgs),
сам zapret — последний релиз [bol-van/zapret](https://github.com/bol-van/zapret).

Главное отличие: **установка переживает обновления SteamOS**.

## Установка

В десктопном режиме откройте Konsole от пользователя `deck` (нужен пароль sudo; если его нет — `passwd`):

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/k0kfjjfkdjf/decke-port_Snowy-Fluffy-zapret/main/installer.sh)
```

Дальше — пункт «Установить Запрет». После установки меню открывается командой `zapret` (в новом терминале)
или ярлыком «Zapret» в меню приложений.

## Что и куда ставится

| Что | Где | Переживает обновление SteamOS |
|---|---|---|
| zapret (релиз bol-van) | `/home/zapret/zapret` | да |
| стратегии и списки | `/home/zapret/zapret.cfgs` | да |
| этот скрипт | `/home/zapret/installer` | да |
| свои стратегия/хостлист | `/home/zapret/custom` | да |
| сервис | `/etc/systemd/system/zapret.service` | да: юниты входят в белый список SteamOS, плюс свой `/etc/atomic-update.conf.d/zapret.conf` |
| команда `zapret`, ярлык | `~/.local/bin`, `~/.local/share/applications` | да |

Read-only и pacman при установке **не трогаются**. pacman нужен только если в системе нет ни `nft`,
ни `iptables`: тогда скрипт предложит поставить `nftables` — с инициализацией ключей
(`pacman-key --init/--populate archlinux holo`), без `SigLevel = Never`, и вернёт read-only как было.
Если после обновления SteamOS `nft` пропадёт, в главном меню есть пункт «Восстановить nftables».

## Отличия от оригинала

- Пути `/opt/zapret/...`, зашитые в стратегиях zapret.cfgs, при применении переписываются на `/home/zapret/zapret/...`.
- Не используется `install_easy.sh` и правка его 238-й строки через `sed`: юнит пишется напрямую.
- Каталог `/home/zapret` принадлежит root (сервис работает от root, а демоны читают списки от пользователя `tpws`).
- Обновление сохраняет твой конфиг и списки (в оригинале из-за `[ CONF_EXISTS = 1 ]` без `$` они затирались на `general`).
  Стратегия из репозитория переприменяется после обновления, только если ты не правил её руками.
- Текущая стратегия и хостлист запоминаются по имени, а не угадываются по хешу.
- Автоподбор стратегии: после теста возвращается твой хостлист; Ctrl+C останавливает проверку
  и применяет лучшую из уже проверенных; домен считается доступным, если прошло TLS-рукопожатие
  (ping не учитывается — на DPI он не влияет и часто режется); не нужен `bc`.
- Только установка из релиза: в git-версии zapret нет готовых бинарников, а компилятора на Деке нет.
- Если до этого zapret ставился оригинальным скриптом в `/opt`, его юниты (`zapret-list-update.timer` и битые ссылки)
  убираются автоматически. Сам `/opt/zapret` исчезнет со следующим обновлением SteamOS.

## После обновления SteamOS

С версии 3.6 SteamOS при обновлении переносит из `/etc` только файлы из белого списка. Юниты `systemd`
в него входят, а порт дополнительно прописывает свой файл в `/etc/atomic-update.conf.d/`.
Если юнит всё же пропадёт, меню само его пересоздаст при следующем запуске `zapret`: всё остальное лежит в `/home`.

В главном меню видно, запущен ли `nfqws` на самом деле, а если установка не найдена, меню перечислит, каких файлов
не хватает, и предупредит о следах оригинального установщика в `/opt`.

## Удаление

Меню → «Удалить Запрет»: останавливает сервис, удаляет юнит, `/home/zapret`, команду и ярлык.
